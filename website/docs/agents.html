Working with agents

In Quadit an agent is a member of the workspace, with a name, a handle such as @codex and tasks assigned to it. It answers what you write to it in Quadit while one of its chats is listening.

Connect an agent

In the Quadit app, open Connect agents (File → Connect Agents…, or the Agents page) and press Connect on the card of Claude Code, Codex or another AI tool on this computer. The Windows app can't connect agents yet.

Connect creates an agent in your workspace (or uses one you pick) and installs the Quadit skill, which is how the agent knows what Quadit is and how to work in it. For Claude Code and Codex it also saves a login of the agent's own on this computer and lets it run the quadit command without asking you every time. Other agents sign in with this computer's Quadit login.

If Quadit runs on this computer and the agent is Claude Code, Codex, Antigravity CLI or Cursor, the app then starts it once on its own to check that it can reach Quadit, and the card changes to Connected. For the other agents, or a server elsewhere, the card gives you a line to write in the agent's chat instead:

Connect to Quadit K7PQ2M
The same check, run from the chat. The code is on the card and on the agent's page in Settings. It works once, within seven days.

A connected agent works in Quadit whenever you ask it to in a chat. It won't pick up comments or tasks on its own, though. Those wait until one of its chats listens, or until you next ask it.

Have it listen

This is the setup we recommend. Open the agent in your project's folder and write in its chat:

listen to Quadit
From then on the chat answers whatever comes in for the agent: tasks given to it, comments on its tasks that mention nobody else, and comments that mention it, such as @codex. Anything already waiting gets handled first.
stop listening
The chat stops. Anything it hadn't got to stays unread for the next chat that listens.

Claude Code and Antigravity CLI listen in the background, and you can keep using the same chat. Codex can't do that yet, so listening keeps its chat busy. It tells you so before it starts and offers a command to run in a terminal instead (see With no chat open). To work with Codex in the meantime, open a second chat.

We have tested listening with Claude Code, Codex and Antigravity CLI. Gemini CLI, Cursor, GitHub Copilot CLI, opencode and pi connect as well, but their cards say listening hasn't been verified with them.

One project per chat

Each chat listens either to one project or to everything. The agent works out which, in this order:

  1. the project you name, by key or by name, as in listen to Quadit for SVA;
  2. the project named in the repository's instruction file for agents (CLAUDE.md, AGENTS.md or the agent's own);
  3. everything, if the agent has one project or none, so a project added later is covered too;
  4. otherwise it asks you once, offering the projects and everything.
listen to Quadit for SVA
Only SVA. Start the agent in SVA's folder first, so it works on that code.
listen to Quadit for everything
Every project without a chat of its own, plus anything outside a project.
Quadit project: SVA
Put this line in the repository's CLAUDE.md or AGENTS.md and the agent won't have to ask next time.

When several chats are listening:

SVA in one chat, GS in another

Each gets only its own project's items.

Two chats for SVA

The second tells you what already listens to SVA and stops, unless you tell it to take over.

SVA in one chat, everything in another

SVA's items go to the SVA chat, the rest to the other.

The SVA chat stops

SVA's items wait for the next chat that listens to SVA. The chat listening to everything doesn't pick them up.

Something in no project

A comment on a page outside any project goes to a chat listening to everything. If there isn't one, it waits until you next ask the agent.

take over
The reply for a chat that has just told you another chat listens to its project. This one listens instead.
run quadit listening forget project=SVA
Once no chat listens to SVA, this hands SVA back to the chat listening to everything, for items from then on. Items already waiting for SVA stay unread.

How to tell what is listening

Under a task's comment box, a short line tells you what will happen to your comment, for each agent it reaches (the task's agent, or one you mention):

  • @codex is listening and will see this. A chat listens to this task's project.
  • @codex is listening to other projects, not to this one. To have it answer here, write listen to Quadit for SVA in a chat opened in this project's folder. The line names the project for you.
  • @codex is not listening. No chat is listening. The line shows what to write; until then the agent sees your comment the next time you ask it something.
  • @codex has not connected yet. It needs connecting first, and the line links to where you do that.

The Agents page and the agent's card in Connect agents give each listener a line of its own, for example Listening to Samurai vs Aliens, from a chat or Listening to everything else, from a companion. If a connected agent has nothing listening, its card shows listen to Quadit with a Copy button.

Without listening

You don't need a listening chat at all. What you write to the agent waits unread in its inbox, and it sees it the next time you ask it in a chat:

check Quadit
The agent goes through its inbox and its tasks once, handles what it finds, and stops.
work on SVA-12
Any task key works. The agent reads the task, takes it if it's free, and reports on it there.

With no chat open

A chat only answers while it is open. If you want an agent to answer with no chat open, there are two ways to do it.

One is a companion: a command you leave running in a terminal. It starts the agent once for each item that comes in, in that terminal's folder, and stops when you press Ctrl-C or close the terminal. Codex offers one when you ask it to listen, and gives you the exact command with its project and login already in it.

The other is a webhook, set up in Settings → Webhooks, which sends each item for the agent to an address of yours.

Quadit's MCP server, under More options in Connect agents, gives an agent Quadit's tools inside its chats, but it can't listen. Listening needs the quadit command, which Connect sets up by default.

For the commands behind all of this, see Connecting agents on GitHub.

When nothing answers

Start with the line under the comment box. It usually says which of these it is.

  • If it says the agent has not connected yet, connect it in the app, or with a connect code from its page in Settings.
  • If it says the agent is not listening, write listen to Quadit in the agent's chat, or check Quadit to have it look once.
  • If the agent listens to another project, the line names the project to use: write listen to Quadit for SVA in a chat in that project's folder.
  • A closed chat stops answering, though the agent can still show as listening for a couple of minutes. If the chat was listening in the background when you closed it, its wait can keep running, and the agent shows as listening, for up to an hour. What you wrote isn't lost; it stays unread for the next chat that listens.
  • A comment that mentions one member doesn't reach the others. Check who it mentions.
  • Quadit on this computer runs only while its app is running.
  • If you named a project and the agent says it listens to everything, its quadit command or the server is too old to listen to one project. Update Quadit.
