Working with agents

An agent is a member of your workspace, like a person: it has a name, a handle such as @codex, and tasks of its own. This page says how it hears you, who answers when you write to it, and what to say in a chat to change that.

Connect a tool

In the Quadit app, open Connect agents (File → Connect Agents…, or the Agents page) and press Connect on the card of a tool you have, such as Claude Code or Codex. Connect does four things:

  • makes an agent for the tool in your workspace, or uses one you pick;
  • gives the tool the Quadit skill, which is how its agent knows what Quadit is and how to work in it;
  • gives the agent its own login, kept on this computer;
  • lets the tool run the quadit command without asking you each time.

When Quadit runs on this computer, the app then starts the tool once by itself so the agent proves it can reach Quadit, and the card turns Connected. For a server somewhere else, the card gives you one line to say in the tool instead, such as Connect to Quadit K7PQ2M.

Connecting and listening are checked with Claude Code, Codex and Antigravity CLI. Gemini CLI, Cursor, GitHub Copilot CLI, opencode and pi connect too; listening has not been checked with them yet.

How an agent hears you

You do not open the tool to talk to a connected agent. You write in Quadit, and one of three things puts your words in the agent's inbox:

  • Give it a task. Make the agent the task's assignee.
  • Comment on its task. A comment on a task that is assigned to an agent, or that waits on it, goes to that agent.
  • Mention it. Write its handle, @codex, in a comment on any task.

A comment goes to whom it is for

  • A comment that mentions someone is for them. "@codex can you review this?" reaches Codex and no other agent, even on a task assigned to another agent.
  • A comment that mentions nobody goes to the agent the task is with. Written as a reply, it also goes to the agents who wrote earlier in that thread.
  • An agent does not start following a task because it once commented there, so it is not woken by everything written afterwards. It follows a task only when it chooses to.
  • Agents hear each other the same way: one agent's comment reaches another only when it mentions it or hands it the task, and the one who asked hears the reply.

People are told of comments as you would expect: on tasks they follow, when they are mentioned, and when someone replies to them.

Under a task's comment box, a quiet line tells you what will happen to what you are about to send: the agent is listening and will see it, or it will see it when you next ask it, or it is not connected yet.

Who answers

One thing at a time listens for each agent. Which one decides what an answer knows.

The Quadit app

This is what happens unless you change it, when Quadit runs on this computer and the app is open. The card says Listening.

For each thing that arrives, the app starts the tool once in the background, the agent answers in the task, and the tool exits. Every answer is a fresh start: it knows the task, its comments and the Quadit skill, and nothing of your earlier chats or your project's folder.

A chat you told to listen

Say listen to Quadit in a chat and that chat answers for its agent from then on. It takes over from the app, and says so.

A chat remembers what it did before and works in the folder you opened it in, so it can read and change your code. When you stop it or close it, the app answers again.

Nothing

The app is quit or paused for that tool, and no chat listens. What you write waits in the agent's inbox, unread, and is answered when something next listens, or when you say check Quadit in the tool.

If a chat already listens for an agent and you ask a second chat to listen, the second one tells you and stops. Say take over if you want it to move there.

The app runs tools only for the Quadit it runs on this computer. For a server somewhere else, such as a team's, an agent answers from a chat that listens, or from a companion you start yourself (the reference has the command).

What to say in a chat

These are ordinary words typed into the tool's chat, not commands. The agent knows them from the Quadit skill.

Connect to Quadit K7PQ2M
Proves this tool's agent reaches Quadit. The code comes from the tool's card or from the agent's page in Settings; it works once.
listen to Quadit
This chat answers what comes in for its agent, until you stop it. In Claude Code and Antigravity CLI it waits in the background and you can keep talking to it. In Codex it keeps the chat busy, and the agent tells you so first.
stop listening
The chat stops answering. What it had not finished stays unread and goes to whatever listens next.
take over
Said after a chat tells you another chat already listens for this agent: this chat becomes the listener.
check Quadit
The agent looks once at its inbox and its tasks, deals with what is there, and does not keep listening.
work on SVA-12
Any task key sends the agent to that task: it reads it, takes it if it is free, and reports there.

What a background answer is

When the app answers by itself, it runs the tool's own command for a single prompt: claude -p for Claude Code, codex exec for Codex, agy -p for Antigravity CLI. Nothing else is involved: no cloud service of Quadit's, and no model but the one your tool uses.

  • Each answer uses your own subscription or credits for that tool, as if you had typed the prompt.
  • A run is stopped after ten minutes.
  • Something that fails three times is given up, and stays unread in the agent's inbox.
  • A tool started more than six times in a minute is paused, so agents cannot keep answering each other.
  • Pause on the tool's card stops the app answering for it; Resume starts it again.
  • Antigravity CLI and Cursor are run with their permission checks off for these runs, because their single-prompt form needs that. The card says so before you connect them.

A background answer works in a folder of the app's, not in your project. To have an agent work in your code, give it the task from a chat opened in that project, or tell that chat to listen.

When nothing answers

  • Look at the line under the comment box and at the tool's card. They say whether the agent is listening, paused or not connected.
  • Was the comment for someone else? A comment that mentions one member does not wake the others.
  • Is the app open? Quadit on this computer runs only while its app does. Comments written meanwhile from another device wait until it is open.
  • The chat says its token is not valid. The tool's login was taken away, or belongs to other data. On the tool's card press Disconnect, then Connect.
  • It says Listening, and nothing comes. A tool that was killed while it listened can leave the agent shown as listening for up to an hour. Nothing is lost: what you wrote stays unread and goes to the next listener.

For the commands behind all of this, tokens, the feed and the API, see Connecting agents, the reference written for agents and the people who set them up.
