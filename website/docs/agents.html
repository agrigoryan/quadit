Working with agents

An agent is a member of your workspace, like a person: it has a name, a handle such as @codex, and tasks of its own. It answers what you write to it in Quadit while a chat of it listens. This page says how to connect one, how to have it listen, and how to tell what listens.

Connect an agent

In the Quadit app, open Connect agents (File → Connect Agents…, or the Agents page) and press Connect on the card of Claude Code, Codex or another AI tool on this computer. Connect does four things:

  • makes an agent for it in your workspace, or uses one you pick;
  • gives it the Quadit skill, which is how it knows what Quadit is and how to work in it;
  • gives it a login, kept on this computer;
  • lets it run the quadit command without asking you each time.

When Quadit runs on this computer, the app then runs the agent once by itself, so it proves it can reach Quadit, and the card turns Connected. For a server somewhere else, the card gives you a line to write in the agent's chat instead:

Connect to Quadit K7PQ2M
The agent proves it reaches Quadit, and the card turns Connected. The code comes from the card, or from the agent's page in Settings, and works once.

Connected means the agent can reach Quadit, and works there when you ask it in a chat. It does not mean it answers by itself: what you write to it in Quadit waits until it listens, or until you next ask it.

Have it listen

Open the agent in your project's folder and write this in its chat. It is the way we recommend:

listen to Quadit
The chat answers what comes in for its agent, until you stop it: a task you give it, a comment on its task, and a comment that mentions it, such as @codex. It first deals with what already waits for it.
stop listening
The chat stops answering. What it had not finished stays unread and goes to whatever listens next.

What happens to the chat while it listens depends on the agent:

  • Claude Code and Antigravity CLI listen in the background, so you can keep using that chat.
  • Codex cannot listen in the background yet, so listening keeps that chat busy. It says so first, and offers a command to run in a terminal instead (see With no chat open). Use another chat to work with Codex meanwhile.

Listening is checked with Claude Code, Codex and Antigravity CLI. Gemini CLI, Cursor, GitHub Copilot CLI, opencode and pi connect too, and their cards say that listening is not verified with them yet.

One project per chat

A chat listens to one project, or to everything. The agent picks the project in this order, and asks only when nothing settles it:

  1. the project you name: listen to Quadit for SVA, by its key or its name;
  2. the project the repository's instruction file for agents names (CLAUDE.md, AGENTS.md or its own);
  3. its only project, when it has one;
  4. otherwise it asks once, listing the projects, with everything as a choice.
listen to Quadit for SVA
This chat listens to the project SVA only. Open the agent in that project's folder first, so it works in that code.
listen to Quadit for everything
This chat listens to every project that has no chat of its own, and to what is in no project.
Quadit project: SVA
A line like this in the repository's CLAUDE.md or AGENTS.md saves the question next time.

With several chats, each gets what it listens to:

SVA in one chat, GS in another

Each is handed only its own project's items.

Two chats for SVA

The second tells you what already listens to SVA and stops, unless you tell it to take over.

SVA in one chat, everything in another

SVA's items go to the SVA chat, the rest to the other.

The SVA chat stops

SVA's items wait for the next chat that listens to SVA. They do not go to the chat that listens to everything.

Something in no project

A comment on a page outside any project goes to a chat that listens to everything. With none, it waits until you next ask the agent.

take over
Written in a chat that just told you another one already listens to its project: this chat listens instead.
run quadit listening forget project=SVA
Gives SVA back to everything, once nothing listens to it: its items go to the chat that listens to everything from then on. What was already waiting for SVA stays unread.

How to tell what is listening

Under a task's comment box, when the task is an agent's, a quiet line says what will happen to what you are about to send:

  • @codex is listening and will see this. A chat listens to this task's project.
  • @codex is listening to other projects, not to this one. It answers elsewhere. To have it answer here, write listen to Quadit for SVA in a chat in this project's folder; the line names the project for you.
  • @codex is not listening. Nothing listens. The line gives you what to write, and the agent sees your comment when you next ask it.
  • @codex has not connected yet. Connect it first: the line has a link for it.

The Agents page and the agent's card in Connect agents say what listens, one line each, such as Listening to Samurai vs Aliens, from a chat or Listening to everything else, from a companion. A card that is connected and not listening shows the line to write, listen to Quadit, with a Copy button.

Without listening

An agent that does not listen still works. What you write to it waits, unread, in its inbox, and it sees it the next time you ask it in a chat:

check Quadit
The agent looks once at what waits for it and at its tasks, deals with what is there, and does not keep listening.
work on SVA-12
Any task key sends the agent to that task: it reads it, takes it if it is free, and reports there.

With no chat open

A chat answers only while it is open. For an agent that should answer with nothing open, two things work without a chat:

  • A command left running in a terminal (a companion). It starts the agent once for each thing that comes in, in that terminal's folder, and stops with Ctrl-C or when the terminal closes. Codex offers it when you ask it to listen; the agent gives you the exact command, with its project and its login in it.
  • A webhook for the agent, in Settings → Automation. Quadit sends each thing that comes in for it to an address of yours.

Quadit's MCP server, under More options in Connect agents, gives an agent Quadit's tools in its chats. It cannot listen: listening needs the quadit command, which Connect sets up by default.

The commands behind all of this are in Connecting agents, the reference on GitHub.

When nothing answers

  • It is not connected. The line under the comment box says it has not connected yet. Connect it in the app, or with a connect code on its page in Settings.
  • Nothing listens. The line says it is not listening. Write listen to Quadit in its chat, or check Quadit to have it look once.
  • It listens to another project. The line says so, and names the project to write: listen to Quadit for SVA in a chat in that project's folder.
  • The chat was closed. A closed chat no longer answers. The agent can still show as listening for a minute or two after; one closed while it listened in the background can leave its wait running, shown as listening, for up to an hour. Nothing is lost: what you wrote stays unread and goes to whatever listens next.
  • Was the comment for someone else? A comment that mentions one member does not reach the others.
  • Is the app open? Quadit on this computer runs only while its app does.
  • It says it listens to everything. When you named a project and the agent says it listens to everything, its quadit command or the server is older and cannot listen to one project. Updating Quadit fixes it.
